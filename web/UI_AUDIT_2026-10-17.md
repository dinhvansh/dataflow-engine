# DataFlow Signalroom — complete frontend design audit (2026-10-17)

## Scope & safety

This audit covers every user-facing view currently routed by `web/src/App.tsx`, all 16 main components and all current shadcn-style UI primitives. **UI-only**: no Go, SQL Server / Epicor, ClickHouse, PostgreSQL, migrations or API endpoint changes. Backend acceptance remains with Codex Local.

## Common components and theme policy

- `Card`, `Badge`, `Button`, `ConfirmActionDialog`, `.field` selectors use semantic tokens.
- Standard backgrounds: Light `#FAFBFA` workspace, pure-white cards/header/sidebar, green `#238047` brand. Dark graphite `#161D1B`, volt `#C0F273`.
- Semantic success/error/warning colors are independent of brand accent. Native checkboxes retain keyboard semantics and use brand accent.
- HTML `<dialog>` for confirmations provides modal focus and Escape, but uses Signalroom styling.
- Static Python browser QA rejects reintroduced `slate`, `sky`, etc. Tailwind palette classes from `web/src/**/*.tsx` and native `window.confirm`.
- UI QA covers every routed view and both Light/Dark states. Screenshots/mock fixtures do **not** establish production readiness.

## Remaining intentional native controls / future UX work

- Standard HTML inputs, selects and textareas remain in several forms, wrapped with the same `.field` styling. This is **not a complete migration to the full shadcn/ui component catalog**, nor is it a bug by itself.
- SQL editors are styled textareas, not Monaco/CodeMirror (syntax highlighting, autocomplete and formatting deferred until usability work is approved).
- Big tables currently use simple HTML table markup or per-page paging; full TanStack Table virtualization/server pagination is not present everywhere.
- Existing API-side gating and QA are required before actual execution of untested backend capabilities.
